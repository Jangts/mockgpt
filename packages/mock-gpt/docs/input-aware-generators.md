# 输入相关的模拟智能生成器

> 文档类型：生成器扩展规划。当前公开接口和默认值见 [使用文档](../README.md)。

## 目标

MockGPT 除固定响应、随机资料和模型 API 包装外，还应提供根据输入生成结果的内置函数。相同配置可接收不同文本，自动产生摘要、要点、标题、字段或带主题的回答，使开发者无需为每段输入手工编写固定结果。

这类函数以可读、输入相关、格式可控和便于测试为目标；摘要是否抓住真正重点、分类是否正确、回答是否合乎语义，不作为通用算法的交付要求。它们不调用真实模型、不下载模型权重、不依赖远端 NLP 服务。固定输出仍是最简单有效的测试方式，内置生成器按需选择。

## 建议能力清单

所有名称为草案，首批范围与后续扩展按下表区分。实现时由一份类型化生成器目录登记名称、参数、输出类型、默认输入与实现入口，驱动导出和相关文档／测试，不建立与运行代码分离的能力清单。

| 生成器 | 输入相关的生成方式 | 典型结果 | 交付建议 |
| --- | --- | --- | --- |
| `summary()` | 分句、代表句选择、去重、按原文顺序拼接 | 一段短摘要 | 首批 |
| `bullets()` | 复用代表句，按条目数量与长度整理 | Markdown 要点 | 首批 |
| `keywords()` | 分词、过滤停用词、词频及稳定排序 | JSON 关键词数组 | 首批 |
| `title()` | 已有标题／首个有效句／高频词组合后限长 | 单行标题 | 首批 |
| `extract()` | 正则捕获、字典和具名字段映射 | 日期、邮箱、金额等 JSON 字段 | 首批 |
| `reply()` | 输入片段、关键词和可选历史片段填入内置／自定义模板 | 带主题的自然语言回答 | 首批 |
| `classify()` | 显式类别词表与匹配得分；无命中走声明的未知类别 | 标签 JSON | 后续 |
| `outline()`／`plan()` | 标题／关键词填充预设章节或步骤模板 | 大纲、执行计划 | 后续，复用文本模板机制 |
| `answer()` | 从明确提供的资料中按词面重合检索句子，再包装回答 | 看似查资料后的答复 | 后续 |
| `fromSchema()` | 按明确支持的 schema 约束生成值，可绑定输入提取字段 | 结构化 JSON 内容 | 后续，优先适配成熟造数库 |

分类、情绪标签、意图名称可复用 `classify` 的机制，不分别建立一套引擎。润色／改写先提供模板式开头结尾、列表转换和词典替换，不承诺任意释义、翻译或逻辑推导。`answer` 仅处理调用方传入的文本，不自动访问 URL、目录或数据库。

已有工具提议生成器继续负责 `tool_calls`；上述 JSON 输出一律作为 assistant 内容，不因为有 `tool`、`intent` 等字段就被升级成执行指令。

## 最简使用与输入选择

```js
// 当前 API。
const mock = new MockGPT({
  rules: [
    { prompt: /总结|摘要/, generator: generators.summary() },
    { prompt: /要点/, generator: generators.bullets({ count: 3 }) },
    { prompt: /关键词/, generator: generators.keywords({ count: 5 }) },
    { prompt: /标题/, generator: generators.title({ maxChars: 24 }) },
  ],
});
```

默认处理当前实例已投影的 `prompt` 文本；规则只负责选用哪种生成器，不承担文本算法。前例允许把指令本身一并处理，不强求理解“请总结以下内容”的自然语言范围；需要严格取正文时由调用方显式选择。

内置文本函数统一接受可选 `source`：固定字符串，或接收生成上下文并返回字符串／`Promise<string>` 的函数。它可读取正则捕获组、完整请求或标准 messages 中指定的文本，也可显式使用网页正文来源。省略 `source` 不需要额外配置；等待来源时传递取消，最终返回非字符串时给出生成错误，不自动把整个请求对象 stringify 成正文。

```js
// 明确只摘要正则捕获到的正文。
{
  prompt: /^请总结[:：]\s*([\s\S]+)$/,
  generator: generators.summary({
    source: ({ match }) => match[1],
    maxChars: 120,
  }),
}
```

支持固定 `source` 也能让 playground 的 `answer` 类场景针对开发者配置的资料响应用户问题；资料作为生成器配置显式提供，不塞进全局隐藏知识库。前端用户不需要了解正则或参数，Skill 可以帮助开发者按需求生成配置。

### 网页访问与总结

提供可选 `sources.web()` 来源，负责“访问 URL → 提取正文”，再把正文交给现有 `generators.summary()`。不另建网页摘要算法；同一来源也能组合 bullets、keywords 或 title。网页抓取真实发生，摘要仍是本地轻量算法，无真实 LLM 参与。

```js
// 网页能力单独导入，基础生成器不引入 DOM 解析依赖。
import { MockGPT, generators } from '@jangts/mock-gpt';
import { sources } from '@jangts/mock-gpt/web';

const mock = new MockGPT({
  rules: [{
    prompt: /https?:\/\//,
    generator: generators.summary({ source: sources.web() }),
  }],
});
// 用户在 playground 输入：请总结 https://example.com/article
```

`sources.web()` 默认从已投影 prompt 读取一个明确的 HTTP／HTTPS URL；URL 缺失、格式错误或出现多个候选时给出可定位错误，不猜测应访问哪一个，也不递归访问页面中的链接。可用 `sources.web({ url: 'https://example.com/article' })` 固定地址，或以 `url: context => ...` 明确选择地址。地址选择与正文提取分开，不能只总结 URL 字符串却表示已经阅读网页。

网页来源作为配置中的显式联网选择。普通 summary、其他纯文本生成器和未使用该来源的 Mock 实例继续离线；规则未命中不能触发访问。模型 API 的目标地址仍仅用于本地协议路由，不被转发到远端模型。网页请求使用独立的内容加载器，不调用 mock.fetch，避免递归进入自身模型路由。

首版读取服务端返回的 HTML 或纯文本。HTML 正文提取优先适配 [Mozilla Readability](https://github.com/mozilla/readability)：通过 DOM 获取文章的 textContent，交给 summary，而非用正则删除全部标签。DOM 解析器禁止执行脚本和加载子资源。Readability 未识别文章时，可退化为过滤 script／style／导航等节点后的文本；诊断标明退化及实际摘要范围。没有可用正文时明确报错，不把空内容包装成成功阅读结果。

HTTP 来源不执行页面 JS，不启动浏览器，不维护登录／Cookie，也不下载 PDF。拒绝访问、HTTP 失败、需要浏览器执行、解码／正文提取错误、超时、超限及空正文分别记录；已知只有登录／验证提示时不能当作文章总结。可显式设置 `sources.web({ fallback: '我目前不支持访问实时网页。' })`，读取失败后以替代来源文本生成正常模拟回复；诊断仍保留 `sourceError` 并标记 `sourceFallback: true`。未配置时继续报错，取消与目标地址校验不兜底。静态 Playground 的浏览器来源另行维护相同的显式提示与取消语义，无需部署浏览器或提供 Cookie。

SDK 的 `/web` 来源由 Node 进程抓取。静态 Playground 另有浏览器来源，使用浏览器 fetch，受目标站 CORS、混合内容等限制，不宣称可访问任意网站。需要 Node 抓取时由使用者显式接入 Node 壳，不额外建立无约束的通用代理接口。

来源配置提供有界默认超时、重定向次数、解压后读取字节与正文分析长度，并传递用户 signal；默认不自动重试或持久化缓存。编码识别在读取字节后处理，避免所有中文页面被固定按 UTF-8 误解码；首批支持编码及不支持时的错误在实现时列明。获取失败不会回退为随机摘要或付费模型调用。超出分析长度时可截取正文并记录范围；传输体积超限时停止下载并报错。

服务端只访问 HTTP／HTTPS，拒绝 URL 内嵌凭据，不转发用户模型请求中的 Authorization／Cookie。默认只允许公开地址；对每次重定向及实际连接地址做一致的解析与目标检查，拒绝本机、私网和链路本地地址，不能只在首次字符串校验后放任重新解析。测试本地站点由受控加载器注入或显式允许的测试目标处理。相关控制在网页加载层统一执行，不要求日常规则配置重复书写。

网页来源保留请求／最终 URL、提取标题、提取方式及截取范围等诊断元数据；summary 默认仍返回纯摘要文本，不将元数据强塞进 assistant 内容。playground 在使用者声明的网页场景中展示输入 URL，并明确页面内容为模拟摘要；若展示获取状态或最终来源，应来自本次真实加载结果而非猜测。

实时页面可能变化，不属于只靠 seed／clock 就能复现的测试。自动化回归注入固定 HTML／文本和响应状态，覆盖正常提取、退化、重定向、取消及读取失败；真人体验可直接访问公开页面，不要求提前制作 fixture。实现顺序在 summary 与异步 source 合同可用后加入网页来源，不先引入浏览器自动化或完整爬虫系统。

## 摘要与要点的默认机制

当前采用有界的抽取式摘要路线：

1. 分句并保留原位置，去除完全重复项；无句界的长行按分句／词边界拆成有界候选。
2. 在全文范围最多采样 180 个候选，构造 TF-IDF 词向量与余弦相似度图，用 [TextRank](https://aclanthology.org/W04-3252/) 风格的迭代排序衡量代表性。全文超过分析预算时采样首／中／尾，不只分析开头。
3. 按 [MMR](https://www.cs.cmu.edu/~jgc/publication/The_Use_MMR_Diversity_Based_LTMIR_1998.pdf) 的相关性与新信息平衡思路，降低近重复句得分，并照顾不同段落区域。
4. 选择过程中计算句数与码点预算，先选择完整、能容纳的代表句，再恢复原文顺序。不能先恢复顺序再取前几句，也不能把一组句子拼好后统一裁切成只有开头。
5. 所有候选都超出预算时才对得分最高句进行有标记的安全裁切；空输入为空内容，不为凑条数编造事实。

使用了 TextRank／MMR 的机制，并增加预算与段落覆盖的工程约束，不声称完全复现论文算法或质量指标。用户不需要学习算法表达式，原有 summary／bullets 接口保持不变。

长度控制独立于重要性排序。`maxChars` 为最多输出的 Unicode 码点数，计入列表标记与分隔符，不能截断代理对；优先保留完整句，单句超限时允许裁切。省略长度参数提供有界默认值，具体值在实现时明确。代码、表格、URL、单句和混合语言都应有可预测退化，不以内容意义是否合理作为失败原因。

中文不能按空格拆词。优先使用 [ECMA-402 的 Intl.Segmenter](https://tc39.es/ecma402/#segmenter-objects)，缺失时采用明确的简单分段后备策略。关键词过滤和句子排序不能使未固定的外部词库或全局状态影响同一次测试。

## 模板回答与有限上下文感

`reply()` 从当前输入提取主题，填入少量内置句式；可按 seed 变化句式，也可传入固定模板。示例效果是“围绕刚才输入的内容产生不同回答”，无需实现开放域问答。

可选地从标准 messages 取最近的 user／assistant 文本片段，使“继续”“换个说法”类场景能复用上轮主题。历史范围由生成器明确限制，仅使用请求携带的消息，不跨请求保存隐形记忆。不依赖 Core 的历史结构，也不把关键词续接当成真正语义理解。

模板组合借鉴 [Tracery](https://github.com/galaxykate/tracery) 的语法展开与变量复用，但基础用法不要求占位符 DSL。需要精确产品话术时，Skill 根据需求／设计产出场景模板和输入来源；请求分支仍由声明式规则负责，不通过 `reply` 暗中接管所有路由。

可考虑提供一份显式启用的演示预设，组合摘要、标题、资料提取及模板聊天，供零配置 playground 使用。任务触发条件、能力与兜底来自同一目录；普通 Mock 实例不自动启用，也不根据任意 system 指令猜测应执行什么算法。

## 结构化生成、可复现与验收

`extract` 的字段由映射声明，支持从输入提取值和字段级默认值；未找到值时按声明返回 null、空数组或省略，不能悄悄随机补事实。需要填充假数据时显式组合造数函数，演示资料不要求真实。

`fromSchema` 可参考 [JSON Schema Faker](https://github.com/json-schema-faker/json-schema-faker) 提供适配，但先明确 schema 方言与支持子集，并验证产物。遇到不支持的约束、矛盾约束或超出生成预算时明确失败；不承诺任意 schema 都能满足，不自动拉取远程 `$ref`。输入字段映射和合成字段分开声明，不把随机数据叫作原文提取。字面量对象仍表示固定 JSON，不自动当作 schema。

验收区分两层：算法结果不要求语义正确；参数与输出合同仍要求正确，包括 JSON 可解析、明确支持的 schema 约束、长度上限、输入相关性、取消与确定性。故意错误数据沿用显式负向测试机制，不通过普通生成器偶然制造。

确定性依赖输入、规则、算法／模板版本、调用顺序、seed 和 clock。采用系统分词时还依赖运行时及语言数据；跨运行时不能只凭相同 seed 承诺逐字一致，严格快照应固定分词实现或测试环境。[Faker 的可复现说明](https://fakerjs.dev/guide/usage)也提醒词库版本与参考日期会影响结果，外部库适配必须使用实例级随机源和时钟。

所有文本分析有输入上限和计算预算，尤其避免长文本的全量两两句子比较。超出预算时按明确策略截取参与分析的文本或报错；默认有界退化，并记录实际处理范围的元数据，不把诊断字段混入模型正文。

首批验证覆盖不同输入确实参与生成、中文／英文与混合文本、空输入、单长句、重复句、码点边界、固定环境复现和超限退化。只保留有必要的最小正式回归样本；算法试验、对比报告与原始语料继续在本地忽略目录维护。
